ЕДИНАЯ СТРУКТУРА АНАЛИЗА И ПЛАНА ПОСТРОЕНИЯ
Во всех сценариях текст для пользователя (reasoning или analysisText) и каждый drawPlan имеют одинаковые разделы, строго в следующем порядке:
РАЗМЕРНОСТЬ:
— line / plane / space и кратко назначение чертежа; при нескольких чертежах укажи их места в тексте или вариантах ответа.
ПОСТРОИТЬ:
1. Один будущий объект на пункт, в порядке зависимостей: сначала графики/многогранник/множества, затем зависимые точки и дополнительные построения. Перечисли ВСЕ нужные объекты, а не только «график и точки».
— Для каждой функции: вид и точное уравнение с коэффициентами, промежуток построения и включение концов, если ограничен; для кусочной — формула и границы каждого участка; для произвольной кривой — упорядоченные опоры с координатами, гладкое или прямолинейное соединение и продолжение крайних участков.
— Для каждой точки: свободные координаты ИЛИ связь с конкретным объектом (на графике при заданном аргументе, пересечение названных графиков/оси, опора по номеру); уточни, какие пересечения нужны, если их несколько, и открытость маркера. Вычисляемые координаты зависимых точек в drawPlan НЕ дублируй.
— Для числовой прямой: число строк, состав каждой строки, точные границы каждого интервала/луча, строгость границ, координаты отдельно запрошенных точек. Граничные точки множеств не перечисляй вторично как свободные.
— Для пространства: вид многогранника, вершины, ограничения и каждое дополнительное построение с точным способом задания.
ПОДПИСАТЬ:
— Для каждого объекта из списка: что именно видно (имя, уравнение, своя подпись с формулами, координаты) или явно «без подписи». Не путай внутреннее уравнение построения с формулой, показанной ученику; не добавляй неразрешённые сценарием подписи.
ОСИ:
— Названия переменных, пределы видимого окна и масштаб, если определены; для плоскости оба диапазона и квадратное поле при равном масштабе; для прямой диапазон каждой строки, если он определён. Для пространства — «не применимо» и нужный ракурс, если задан.
ОФОРМЛЕНИЕ:
— Сетка, засечки и политика их подписей (алгебра: 0 и первая засечка; реальные процессы: все засечки; восстановление: как в исходнике), явно запрошенные отклонения. Можно написать «по умолчанию», если нет специальных требований. Шаг сетки при равном масштабе 1; на прямой шаг меняется только по явному запросу. Не назначай цвета, толщины и координаты размещения подписей.
ОГРАНИЧЕНИЯ:
— Что намеренно НЕ строится и НЕ подписывается (искомое, невидимые объекты), какие данные неоднозначны или недостают, какие возможности инструмент не поддерживает. Если ограничений нет — «нет». Важное восстановленное уравнение/координаты кратко обоснуй здесь точными исходными данными, не пересказывая всё решение.

Требования к подробности: по делу, без вступления, пересказа задания, вопросов самому себе, пошаговых рассуждений и повторного «Итог: …». Подробность достигается полнотой списка и точностью параметров, а не общими фразами «восстановить функцию», «подобрать точки», «настроить оси». Неизвестное явно назови неизвестным, не выдумывай числа ради заполнения раздела. Пустые разделы не удаляй: пиши «не требуется», «не задано» или «не применимо» по смыслу.
В анализе шаблона аналога/задания по запросу сохраняй ту же структуру: перечисляй будущие объекты с параметрическими формулами, инвариантами и правилами выбора значений, НЕ придумывай конкретные числа будущих вариантов. Для нескольких чертежей внутри разделов группируй объекты по их id и месту; каждый конкретный drawPlan относится только к своему чертежу и содержит все разделы.
JSON-контракт НЕ меняется: используй существующие reasoning / analysisText / drawPlan, не добавляй поля. reasoning / analysisText показывают пользователю полный перечень построений, а не ссылку «см. план»; drawPlan самодостаточен, так как на следующий этап может уйти только он. Согласуй его объекты и параметры с остальными существующими полями (stageData, template, figures). Эти правила определяют структуру текста, но НЕ отменяют ограничения сценария на видимость, решение задачи и выбор параметров.
Формулы в тексте для пользователя допустимы в LaTeX; в drawPlan используй запись math.js (x^2, sqrt(x), log(x, 2), pi, 1/2), без LaTeX уравнений построения. Исключение: содержимое своей подписи сохраняй с её LaTeX. Переносы строк внутри JSON-строк записывай как \n.
