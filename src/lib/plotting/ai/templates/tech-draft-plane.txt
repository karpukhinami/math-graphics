(Общий блок для всех сценариев. Правила ниже не зависят от того, откуда взят план.)

ЧТО КОНСТРУКТОР ДЕЛАЕТ САМ (не вычисляй и не пиши)
— Координаты пересечения графиков (тип intersection) и y точки на графике (тип onGraph).
— Шаг сетки (для сопоставимых осей 1 клетка = 1 единица), деления и числа на осях, масштаб осей, пропорции картинки, цвета, толщины, стили, расположение подписей, внутренние номера.
— Поле, которое не нужно, просто НЕ пиши: отсутствующее поле = значение по умолчанию (авто).

ТИПЫ ГРАФИКОВ
— Формула y = f(x) → explicit; равенство с x и y или вертикальная прямая x = a → implicit; разные формулы на участках → piecewise.
— Гладкий график через точки (кривая без формулы, схематичный график) → points + connect "smooth".
— Ломаная, кусочно-линейная функция, отрезок → points + connect "segments".
— Перпендикуляры из точки на оси → флаги dropToXAxis / dropToYAxis (и labelOnAxes для значений на осях).

ТИПЫ ТОЧЕК — ЖЁСТКИЕ ПРАВИЛА (проходи сверху вниз, остановись на первом подходящем)
1. Пересечение двух графиков плана («пересечение», «общая точка», «решение системы», «первая/вторая по порядку» и т. п.) → ТОЛЬКО "intersection". Тип "coords" ЗАПРЕЩЁН.
2. Точка на графике плана при заданной абсциссе → ТОЛЬКО "onGraph" (только x).
3. Опорная точка графика, заданного по точкам (вершина, экстремум, заданная точка) → ТОЛЬКО "graphPoint".
4. Иначе, если точка задана числами и не связана с графиками → "coords".
Дополнительно:
— Если рядом с точкой в плане написаны координаты, а точка — пересечение или лежит на графике, координаты ИГНОРИРУЙ: конструктор найдёт точку сам и точнее. Не вычисляй, не переписывай и не округляй их.
— Перед выбором "coords" проверь, не лежит ли точка на графике плана: на одном графике → "onGraph"; на двух → "intersection".
— "intersection" отмечает ВСЕ пересечения внутри пределов осей. Нужна одна точка из нескольких — это достигается пределами осей из плана; не заменяй "intersection" на "coords".
— ЗАПРЕТ СВОБОДНЫХ ТОЧЕК: точку "coords", не привязанную ни к одному графику, ставить НЕЛЬЗЯ, если отдельная точка с координатами не оговорена ЯВНО в плане. Не добавляй «для наглядности» точки на осях, в начале координат, вершины, корни. Сомневаешься — точку не ставь.

ПРЕДЕЛЫ ОСЕЙ
— Пределы бери из плана ровно такими, как записаны. Все объекты плана должны помещаться внутри.
— Если пределов в плане нет: все объекты с запасом 5–10 %, удобные целые границы, размахи по x и y почти равны (квадратное поле, недостающее — пустым местом), не менее 6 единиц на каждой оси.
— ЖЁСТКИЙ ЗАПРЕТ: шаг сетки НЕ задаётся. Полей xStep / yStep в схеме НЕТ. При одинаковом масштабе осей шаг всегда 1, это делает конструктор. Подписи на осях по умолчанию — 0 и первая засечка; если план требует «подписать все засечки» (графики реальных процессов), пиши axes.axisMarks = "all".

ПОСТРОЕНИЕ НА ПРОМЕЖУТКЕ
— График не обязан занимать всё поле: у него можно задать промежуток, на котором он рисуется, — "domain": { "from": ..., "to": ... }. Вне этого промежутка линия не появляется, даже если до краёв поля ещё далеко.
— Пиши domain, когда план ограничивает функцию: «y = …, x ∈ [0; 5]», «при x ≥ 1», «на отрезке [−2; 2]», «для t от 0 до 10», «функция определена при …»; и когда по картинке кривая явно начинается или обрывается внутри поля, а не у его краёв.
— from/to — выражения math.js ("0", "1/2", "2*pi"); "" с нужной стороны = без ограничения, тогда линия идёт до края поля (луч).
— domain и пределы осей — разные вещи: axes задают видимое окно, а domain — где существует сама линия. Если по условию функции хватает только части поля, НЕ растягивай линию на всё поле; и не сужай domain ради композиции — для этого есть пределы осей. Промежуток должен целиком попадать в пределы осей, иначе его не видно.
— На границе промежутка линия обрывается. Если по плану этот конец не входит (строгое неравенство, выколотый конец), добавь точку { "type": "onGraph", "graph": "gN", "x": "граница", "open": true }; если входит — дополнительно ничего не нужно.
— domain подходит для explicit, implicit и графика по точкам (у графика по точкам продолжение за крайние опоры отключают extendEnds: false); у piecewise границы задаются у каждого участка своими from/to — общий domain там не пиши.

СХЕМА ОДНОГО ЧЕРТЕЖА
[!] — обязательно, [редко] — без веской причины не писать, [по плану] — только если есть в плане.
{
  "axes": {
    "xMin": string, "xMax": string, "yMin": string, "yMax": string,   [!]
    "xName"?: string, "yName"?: string,             [редко] ИМЯ ПЕРЕМЕННОЙ (одна буква, напр. "t"), а не словесное название оси
    "xLabelFormat"?: "number" | "pi" | "fraction",  [редко] "pi" — тригонометрия; по умолчанию "number"
    "yLabelFormat"?: "number" | "pi" | "fraction",  [редко]
    "axisMarks"?: "all"                             [по плану] только если план просит подписать все засечки (графики реальных процессов); иначе не пиши
  },
  "grid"?: boolean,          [редко] false — только если план требует чертёж без сетки
  "graphs": [ GRAPH, … ],    [!] может быть пустым массивом
  "points": [ POINT, … ]     [!] может быть пустым массивом
}
Числа и пределы — строки math.js: "-5", "1/2", "2*pi", "sqrt(2)".

GRAPH (у каждого "id": "g1", "g2", … — на него ссылаются точки):
  { "id": "g1", "type": "explicit", "expression": "x^2 - 2*x" }          — expression без «y =»
  { "id": "g2", "type": "implicit", "equation": "x^2 + y^2 = 25" }
  { "id": "g3", "type": "piecewise", "pieces": [
      { "expression": "x", "from": "", "to": "0", "includeFrom": false, "includeTo": false },
      { "expression": "x^2", "from": "0", "to": "", "includeFrom": true, "includeTo": false } ] }
      from/to "" — без ограничения; includeFrom/includeTo — входит ли граница (закрашенный/выколотый конец).
  { "id": "g4", "type": "points", "connect": "smooth" | "segments",
    "through": [ { "x": "-2", "y": "1" }, { "x": "0", "y": "3", "extremum": "max" }, { "x": "3", "y": "1" } ],
    "extendEnds"?: true }
      ≥ 2 точки с разными x; extremum "min"|"max" — только для smooth; extendEnds — только если план просит продолжить за крайние точки.
  Необязательно у любого графика:
    "label"?: string                            [по плану] короткое имя функции, например "f"
    "labelMode"?: "none" | "name" | "equation" | "custom" [по плану] вид подписи, правила в общем блоке выше
    "customLabel"?: string                      [по плану] текст с формулами $…$ только при labelMode = "custom"
    "domain"?: { "from": string, "to": string } [по плану] промежуток, на котором рисуется график — см. раздел «ПОСТРОЕНИЕ НА ПРОМЕЖУТКЕ»

POINT:
  { "type": "coords", "x": "2", "y": "3" }
  { "type": "onGraph", "graph": "g1", "x": "2" }
  { "type": "intersection", "graphs": ["g1", "g2"] }      — разные имена нескольким точкам: "labels": ["A", "B"] слева направо
  { "type": "graphPoint", "graph": "g4", "index": 2 }     — номер точки в through, с 1
  Необязательно у любой точки:
    "label"?: string          [по плану] имя точки
    "showCoords"?: boolean    [по плану] показать координаты (значение по умолчанию — по правилам подписей выше)
    "open"?: true             [по плану] выколотая точка
    "dropToXAxis"?: true, "dropToYAxis"?: true   [по плану] перпендикуляры на оси
    "labelOnAxes"?: true      [по плану] значения в основаниях перпендикуляров

ПРИМЕР ОДНОГО ЧЕРТЕЖА (план: явная функция y = log(x, 2) - 3; точка на графике 1 при x = 4, подписать A; оси x от -1 до 10, y от -5 до 4)
{
  "axes": { "xMin": "-1", "xMax": "10", "yMin": "-5", "yMax": "4" },
  "graphs": [ { "id": "g1", "type": "explicit", "expression": "log(x, 2) - 3" } ],
  "points": [ { "type": "onGraph", "graph": "g1", "x": "4", "label": "A" } ]
}

ПРИМЕР С ПРОМЕЖУТКОМ (план: y = sqrt(x) на промежутке 0 ≤ x < 4; правый конец — выколотая точка A)
{
  "axes": { "xMin": "-1", "xMax": "6", "yMin": "-1", "yMax": "4" },
  "graphs": [ { "id": "g1", "type": "explicit", "expression": "sqrt(x)", "domain": { "from": "0", "to": "4" } } ],
  "points": [ { "type": "onGraph", "graph": "g1", "x": "4", "label": "A", "open": true } ]
}
