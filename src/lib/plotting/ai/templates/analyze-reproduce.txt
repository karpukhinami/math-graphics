ЗАДАЧА ПЕРВОГО ЭТАПА (анализ, без построения JSON-сцены)
Пользователь хочет ВОСПРОИЗВЕСТИ изображение из исходного материала средствами нашего инструмента Plotting.

ВАЖНО
— Анализируй ТОЛЬКО то, что уже содержится в исходном материале.
— Нельзя решать задачу или добавлять новые математические данные, которых нет во входе.
— Особенно внимательно обрабатывай изображения.

ТОЧНОСТЬ КООРДИНАТ — ГЛАВНОЕ ТРЕБОВАНИЕ
— Максимально точно считай координаты всех опорных точек: привязывай их к линиям сетки, засечкам и подписям осей, а не к «примерному» положению.
— Явно отмеченные на рисунке точки передавай с точными координатами (целыми или простыми дробями, если они лежат на узлах/засечках).
— Если график — известная функция (прямая, парабола, гипербола, корень, модуль, показательная, логарифм, тригонометрия), по опорным точкам восстанови ТОЧНОЕ уравнение и проверь его подстановкой каждой точки.
— Если график не описывается простой формулой (произвольная кривая, ломаная) — передай в stageData.planePoints и в notes функции упорядоченный по x набор опорных точек: концы, вершины/экстремумы, изломы, пересечения с осями, точки на узлах сетки. Такой график будет построен по точкам, поэтому точек должно хватать, чтобы форма совпала.
— Не выдумывай точки и объекты, которых нет на рисунке.

УТОЧНЕНИЯ ПОЛЬЗОВАТЕЛЯ (координаты точек, ожидаемое уравнение и т. п.)
{{USER_REFINEMENTS}}
— Эти уточнения имеют приоритет над тем, что ты считал с изображения: если пользователь указал координаты или уравнение, используй именно их и согласуй с ними остальное.

Если на изображении график на координатной плоскости:
— Не ограничивайся общей формой («парабола», «гипербола», «прямая») — по максимуму определи ТОЧНОЕ уравнение каждой функции.
— Используй подписи осей, засечки, сетку, отмеченные точки, пересечения с осями, вершину, асимптоты.
— Считывай координаты опорных точек с изображения и восстанавливай коэффициенты.
— Если несколько графиков — уравнение для каждого.
— В analysisText укажи y = … (или F(x,y) = …) и кратко — как получено.
— Если точное уравнение однозначно не восстановить — наиболее вероятное с обоснованием и опорные точки в stageData.
— Пределы отображаемой области по осям (примерные допустимы).
Не восстанавливай на этом этапе мелкие визуальные настройки (цвета, толщины).

Если изображена числовая прямая, определи:
— координаты отмеченных точек;
— интервалы и лучи, если показаны;
— kind (interval / ray), display (hatchRight / hatchLeft / arc), открытость границ.
В stageData.lineSets укажи структуру множества; НЕ перечисляй граничные точки отдельно — они создаются из множества автоматически.
Для одной прямой: axisRowCount: 1, axisRow: 0. Если на рисунке нет делений оси — majorVisible: false.

ЧТО УМЕЕТ НАШ ИНСТРУМЕНТ — см. sceneType "plane" и "line" как в режиме построения по заданию.
Если воспроизвести содержательную часть нельзя — canDraw = false.

{

    "lineSets": [ { "input": string, "description": string } ],

    "visualNotes": string
  }
}

analysisText — описание для пользователя: что будет воспроизведено и на каких данных это основано.
