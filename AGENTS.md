# Project rules

- Embedded plot SVGs pass through `plotting/standalone-svg.ts` with KaTeX CSS and inline fonts. Why: SVG images cannot inherit page styles.
- Number-line labels use exact rational arithmetic in `line/numeric-labels.ts`, deriving tick labels from the original minimum and step; parsed interval endpoints retain source expressions through normalization and boundary edits. Why: coordinates stay exact and fraction/decimal presentation never relies on rounded geometry.
- Graph captions are derived in `graph-labels.ts`, rendered with KaTeX in `graph-caption-layout.ts`, placed through `label-layout.ts` using visible curve anchors; persist only caption mode and user text, never layout coordinates. Why: preview, embeddings and exports share collision-aware labels that adapt to scene edits.
- The app is a math plotting tool (line / plane / space); `/` is the landing page, `/plot` the plotting page, `/workspace` the task editor that embeds plots. Do not reintroduce infographic or style-profile code.
- The plotting UI lives in `PlotWorkbench`, reused by `/plot` and the `/workspace` plot dialog; never fork plotting logic for the editor. Why: plotting improvements must reach every embedding.
- Entry points reset sessions before importing originals, never on workbench unmount; guard async results by mount/sessionVersion and key previews by version. Why: old dialog teardown must not erase a reopened editor.
- Beautification uses a versioned template selected in `plotting/beautify.ts` (legacy file kept); charts use native PNG export, plots use preview PNG capture, both through the same image client; result and busy state pass through the workbench to insertion dialogs, batched via `workspace/plot-insertion.ts` with scene only on the original. Why: one-value prompt rollback and no lost artwork.
- All AI calls go through `src/lib/ai/client.ts` -> `/api/ai/text` and `/api/ai/image` (OpenRouter, key `OPENROUTER_API_KEY` read server-side in `openrouter.server.ts`). Why: one thin provider-specific layer.
- Plotting analysis and verbal construction plans share one structure template injected by prompt builders. Why: every scenario lists future constructions consistently without changing JSON contracts.
- Point-defined graphs share anchors and extendEnds; preserve qualitative for saved smooth graphs, piecewise-linear with exact sorted vertices for straight segments. Why: JSON compatibility and exact corners across rendering and point solving.
- Document parsing (PDF/DOCX) for AI source material is done in `/api/extract-document`. Why: those parsers need the server runtime.
- Scene JSON save/load lives in `src/lib/plotting/scene-json.ts` (space part in `space/serialize.ts`): save only user/AI input, omit defaults; a missing field means "auto". Loading keeps accepting the old full format, covered by `tests/scene-json.test.ts`. Why: compact files that always rebuild to the same picture.
- Plane axis intersection targets use reserved `axis:x=0` / `axis:y=0` references resolved only for solving, never added to scene graphs. Analytic/smooth graphs solve the source equation with residual-checked sign roots and local minima in `axis-intersections.ts`; other pairs keep segment solving. Why: axis points stay dependent and tangencies between vertices are not missed.
- Plane axes split `name` (variable used in formulas) from optional `label` (verbal caption drawn on the axis); AI drafts use xName/yName + xCaption/yCaption, and `axisLabelText` prefers the caption. Why: equations stay correct while the axis can read «время».
- Negative-edge arrow/grid extensions in `render.ts` leave math bounds and clipping unchanged; caption coordinates are shared with collision checks. Why: readable axes without saved layout state.
- Point labels render `A_1` as A with a subscript via `pointLabelTspans` in render.ts; measurement uses the underscore-stripped plain form. Why: SVG text has no KaTeX, so subscripts are explicit tspans.
- Store input actions rebuild committed constructions and dependencies; spatial vertex text commits on blur, drafts excluded; line batch building assigns completed sets after boundary synchronization. Why: geometry updates without a build-all button or premature draft insertion.
- Workspace inline-image editing uses presentation-only Markdown ranges in `workspace/text-segments.ts` and a selection handle mapping local offsets to the full source. Why: images appear in place without changing stored plot tokens or generation input.

- Read subdirectory `AGENTS.md` before edits (plotting/ai, plotting/chart, workspace have their own).
- AI flows run analysis and drawing behind one «Нарисовать» action; analysis text is shown only when drawing is impossible, progress steps go to the preview area (or the button where there is none). Why: users see one step, not intermediate reasoning.
- Root error boundary and `vite:preloadError` reload once on stale chunk errors after a redeploy. Why: open tabs otherwise break with «Failed to fetch dynamically imported module».
