================================================================================
0. СОГЛАШЕНИЯ ДОКУМЕНТА
================================================================================

0.1 Обозначения
  "поле: тип"            — поле JSON и его тип.
  `строка-выражение`     — строка, которая разбирается как математическое выражение
                           (см. раздел 5.1), а не как «просто текст».
  ВХОД                   — поле, которое задаёт пользователь (определяет чертёж).
  ВЫХОД / runtime        — поле, которое вычисляется программой при «Построить»
                           (built, dirty, error, locked, kindLocked, index и т. п.).
                           Для описания чертежа его задавать не нужно; при импорте
                           оно перестраивается из ВХОДА.
  ДЕФОЛТ                 — значение при создании объекта через UI.
  ВИДНО                  — что именно появляется на SVG-чертеже.
  НЕ ВИДНО               — поле существует, но на чертеже ничего не меняет.

0.2 Единый контракт
  Все три режима — это один JSON `PlotScene` (version = 1). Режим задаёт поле
  `space`: "line" | "plane" | "space". Остальные режимы в JSON присутствуют как
  пустые/нейтральные значения.

  PlotScene {
    version: 1
    space: "line" | "plane" | "space"
    axisScaleMode: "equal" | "independent"        // только plane
    plotAspectRatio: "1:1"|"4:3"|"3:2"|"16:9"|"3:4" // только plane + independent
    xAxis: AxisSpec                               // plane
    yAxis: AxisSpec                               // plane
    grid: { visible: boolean }                    // plane
    appearance: PlotAppearance                    // plane и line
    graphs: SceneGraph[]                          // plane
    points: ScenePoint[]                          // plane
    tangents: []                                  // ЗАРЕЗЕРВИРОВАНО, не рисуется (см. 6)
    customColors: string[]                        // пользовательские цвета палитры UI; на чертёж не влияют
    line: LineSceneData | null                    // не null только при space="line"
    space3d: SpaceSceneData | null                // не null только при space="space"
  }

0.3 Цвета
  Строка hex "#RRGGBB". Базовая палитра PLOT_PALETTE (по порядку):
    1 "#29A2E5" (синий), 2 "#FF9935" (оранжевый), 3 "#FF3C8A" (розовый),
    4 "#9050C7" (фиолетовый), 5 "#5DBB3B" (зелёный), 6 "#31C2A7" (бирюзовый).
  Дефолтный цвет n-го объекта (n = index, с 1): PLOT_PALETTE[(n-1) mod 6].
  Исключения: точка plane — всегда PLOT_PALETTE[0]; точка line — "#29A2E5".

0.4 Идентификаторы
  id — произвольная уникальная строка. Ссылки между объектами идут по id
  (graphId, sourceSetId, pointAId, planeId ...). Ссылка должна указывать на
  существующий id, иначе объект получит error при построении.

0.5 Что такое «построено»
  Объект рисуется только если он построен (plane: built != null; line: built != null;
  space: built == true) И его style.visible == true. Пока пользователь не нажал
  «Построить/Отметить», объект на чертёж не попадает.

0.6 Сохраняемый JSON (version = 2, компактный) и правило «авто»
  Кнопка «Сохранить JSON» пишет ТОЛЬКО ВХОД. Всё, что конструктор вычисляет сам,
  не пишется и пересчитывается при загрузке (файл или ответ ИИ). Загрузка
  принимает и старый полный формат version = 1 (лишние поля пересчитываются).

  ПРАВИЛО «АВТО»: отсутствующее поле = значение подставляет код.
    - любое поле style/appearance/ticks/view, равное дефолту, не пишется;
    - цвет объекта не пишется, если он равен цвету палитры по номеру объекта;
    - index не пишется (номер = позиция в массиве); id пишется только там,
      где на объект ссылаются (graphs, points, sets, объекты пространства);
    - пустая строка в шаге сетки (xAxis/yAxis.gridStep) = «авто»:
      equal -> 1, independent -> подбор niceStep по пределам оси; в UI поле
      показывает подсказку «авто». Шаг, совпадающий с авто, сохраняется как авто;
      labelStep, совпадающий с шагом сетки, не пишется;
    - built, dirty, error, locked, kindLocked, geometry, figure, fit* — никогда.

  ЧТО ДОСЧИТЫВАЕТ КОНСТРУКТОР (признак в JSON -> что вычисляется):
  Плоскость
    graphs[].math.kind + свои поля (explicit: expression; implicit: equation;
      piecewise: pieces; qualitative/piecewise-linear: anchors, extendEnds
      (пишется только false)) -> ломаные кривой (built.segments).
      Поля других видов задания не пишутся.
    points[].math.mode = "plane"        -> хранятся x и y (обе — ВХОД).
    mode = "onGraph" + graphId + x      -> y вычисляется по графику (не хранится).
    mode = "onGraph"/"anchor" + graphId + anchorIndex -> обе координаты берутся
                                          из опорной точки графика.
    mode = "intersection" + graphId + graphIdB -> все точки пересечения в
                                          текущей области вычисляются кодом.
  Несколько решений у одной точки (несколько пересечений, вертикаль через
  неявную кривую, разрыв кусочной функции): в JSON это ОДНА запись точки,
  в конструкторе — отдельное «облачко» на каждое решение. Индивидуальные правки
  решений хранятся в points[].solutions: [{ show?: false, style?: {...} }, ...]
  по номеру решения (решения упорядочены так, как их находит конструктор);
  координаты в solutions не хранятся, пустые хвостовые элементы не пишутся.
  Пример: { "math": {"mode":"intersection","graphId":"g1","graphIdB":"g2"},
            "solutions": [ {"style":{"label":"A"}}, {"style":{"label":"B"}} ] }
  У кусочной функции открытость решения на разрыве задаёт конструктор.

  Прямая
    sets[].math.kind + свои поля (interval: left,right,leftOp,rightOp;
      ray: rayOp,rayBoundary; freeform: freeformInput) -> разбор множества.
    Граничные точки множеств (math.sourceSetId + boundaryKey) создаёт сам
      конструктор: координата, открытость и цвет (если style.colorManual
      не true) вычисляются из множества. В JSON такая точка пишется только если
      пользователь изменил её оформление (подпись, показ координаты и т. п.) —
      и без coordinate/open.
    Свободные точки: math.coordinate — ВХОД.
    axisRowCount пишется только если > 1.

  Пространство
    shapeKind + baseVerticesInput + figureConstraints -> вершины, рёбра, грани
      (figure не хранится).
    points[].definition — ВХОД; исключения:
      onFace + placement "center"  -> faceU/faceV не пишутся (центр грани);
      onLine + ratioMode "explicit" -> lineParam не пишется (из ratioA:ratioB);
      onLine + ratioMode "auto"     -> ratioA/ratioB не пишутся, хранится lineParam.
      linePlaneIntersection / planeEdgeIntersection / planeIntersectionBoundary
      -> координаты всегда вычисляются.
    label пишется, если не пустой; built пишется только как false.
    view и appearance — только отличия от дефолта.



================================================================================
1. РЕЖИМ «ПРЯМАЯ» (1D) — space = "line"
================================================================================

1.1 Что это
  Одна или несколько горизонтальных числовых осей (рядов), друг под другом.
  На осях можно изобразить: множества (интервалы, лучи, объединения) штриховкой,
  дугой или жирным отрезком; точки (закрашенные/выколотые) с подписью и
  координатой; пунктирные вертикальные «перпендикуляры» через все ряды.

1.2 Фиксированные параметры холста
  Ширина холста ВСЕГДА 720 px (поле appearance.width для line игнорируется).
  Высота = rows*144 + (rows-1)*56 + 2*pad, где rows = line.axisRowCount,
  pad = max(16, appearance.padding). Ось в ряду расположена на 62% высоты ряда.
  Для line при создании: appearance = DEFAULT_APPEARANCE с width=720, height=144,
  frame=false, padding=16. Сетки нет (grid.visible=false).
  Поля xAxis/yAxis/graphs/points/tangents в режиме line не используются.

1.3 Структура line: LineSceneData
  {
    axis: LineAxisSpec
    ticks: LineTickSettings
    axisRowCount: number          // >= 1, число рядов осей
    sets: SceneSet[]
    points: SceneLinePoint[]
  }

1.4 Ось: line.axis
  name: string        // имя переменной, подпись у стрелки. Пусто -> "x". ДЕФОЛТ "x"
  unit: string        // единица; подпись "name, unit". ДЕФОЛТ ""
  min: `строка-выражение`   // левый предел шкалы. ДЕФОЛТ "-5"
  max: `строка-выражение`   // правый предел шкалы. ДЕФОЛТ "5"
  majorStep: `строка-выражение`  // шаг больших засечек, > 0. ДЕФОЛТ "1"
  Условия: max > min, majorStep > 0, иначе чертёж не строится (SVG = null).
  Геометрия: видимая область оси шире на полшага: [min - step/2, max + step/2].
  Правый конец оси = основание стрелки; сама стрелка (длина appearance.arrowSize,
  ДЕФОЛТ 24) торчит правее.
  ВАЖНО: большие засечки отсчитываются от min (min, min+step, ...), а НЕ от нуля.
  Если (max-min) не делится на step нацело — UI показывает предупреждение, чертёж
  строится, последняя засечка не попадает на max.
  Подпись оси (name[, unit]) — курсивом под осью, у правого края.

1.5 Засечки: line.ticks (LineTickSettings)
  majorVisible: boolean
      true  -> на каждом ряду рисуются большие засечки (ДЕФОЛТ true)
      false -> засечек нет; подписей больших засечек тоже нет
  majorLabelMode: "all" | "firstTwo" | "givenTwo" | "selected" | "none"
      "all"       подписаны все большие засечки (ДЕФОЛТ)
      "firstTwo"  подписаны только первые две (от левого края)
      "givenTwo"  подписаны две засечки, начиная с majorLabelAnchor
                  (если anchor не совпадает с засечкой — подписей нет)
      "selected"  подписаны засечки, значения которых перечислены в
                  majorSelectedLabels
      "none"      подписей нет, засечки остаются
  majorLabelAnchor: `строка-выражение`   // для "givenTwo"
  majorSelectedLabels: string             // для "selected": значения через ";" (точка с запятой)
  minorEnabled: boolean                   // мелкие засечки. ДЕФОЛТ false
  minorDivisions: `строка-выражение`      // N: каждый большой интервал делится на N частей
                                          // (N >= 2, иначе мелких нет). ДЕФОЛТ "5"
  minorLabelMode: "all" | "oneInterval"
      "all"         подписаны все мелкие засечки (шрифт 60% от обычного)
      "oneInterval" подписаны мелкие засечки только внутри одного большого
                    интервала [minorLabelIntervalStart; +majorStep)
  minorLabelIntervalStart: `строка-выражение` // начало интервала для "oneInterval"
  Размеры: длина большой засечки = appearance.tickSize (ДЕФОЛТ 6, в обе стороны от оси),
  мелкая = 60% от неё, толщина мелкой = 60% от tickWidth (ДЕФОЛТ 2).
  Формат подписей засечек всегда "number" (десятичная запятая: 0,5).
  Мелкие засечки подписываются только если minorEnabled = true.

1.6 Ряды осей
  axisRowCount: number >= 1. Каждый ряд — отдельная ось с теми же min/max/ticks.
  Объекты (множества и точки) привязаны к ряду полем axisRow (0 — верхний ряд).
  axisRowCount автоматически становится >= max(axisRow)+1.
  Типичный сценарий: несколько множеств друг под другом (пересечение/объединение
  на разных осях) + пунктирные перпендикуляры через точки.

1.7 Множества: SceneSet
  {
    id: string, index: number (ВЫХОД), axisRow: number
    math: SetMath
    style: SetStyle
    kindLocked: boolean (ВЫХОД: после первого построения способ задания нельзя менять в UI)
    built: BuiltSet | null (ВЫХОД), dirty, error (ВЫХОД)
  }

1.7.1 SetMath — способ задания (math.kind)
  kind: "interval" | "ray" | "freeform"

  kind = "interval"  (конечный интервал; в принципе допускает ±inf в границах)
    нужны: left, right: `строка-выражение` (допустимы "-inf","+inf","inf","∞","-∞"),
           leftOp: "<" | "<="  ,  rightOp: "<" | "<="
    Смысл:  left leftOp x rightOp right  в терминах включения границ:
      leftOp  "<"  -> левая граница ВЫКОЛОТА (строгое);  "<=" -> ВКЛЮЧЕНА
      rightOp "<"  -> правая граница ВЫКОЛОТА;           "<=" -> ВКЛЮЧЕНА
    ДЕФОЛТ: leftOp "<", rightOp "<=".
    Ошибка, если left > right.  Если границы равны — это вырожденный интервал:
    чертится только точка-граница без штриховки (площади нет).
    Для бесконечной границы ставьте строгий оператор ("<"), иначе в записи
    множества будет "[−∞".

  kind = "ray"  (луч)
    нужны: rayBoundary: `строка-выражение`, rayOp: "<" | "<=" | ">" | ">="
      "<"   -> (-inf; b)       "<=" -> (-inf; b]
      ">"   -> (b; +inf)       ">=" -> [b; +inf)
    ДЕФОЛТ rayOp ">=".  Поля left/right/leftOp/rightOp игнорируются.

  kind = "freeform"  (свободная запись, в том числе объединение)
    нужно: freeformInput: string — список интервалов через ";" на нулевой
    глубине скобок. Каждый интервал: открывающая "(" или "[", левая граница,
    ";" , правая граница, закрывающая ")" или "]".
    Пример: "(-inf; -2]; (3; +inf)"   или   "[1; 2]; [4; 7)"
    Правила:
      - бесконечность допускается только с круглой скобкой;
      - левая граница > правой -> ошибка;
      - границы равны и скобки не обе квадратные -> ошибка;
      - интервалы сортируются и склеиваются (пересекающиеся/касающиеся с
        включённой границей сливаются; (a;b) и (b;c) без включения b остаются
        раздельными — точка b выколота);
      - "[2; 2]" допустим: единственная точка.
  Остальные поля math, не относящиеся к выбранному kind, на чертёж не влияют.
  Границы в выражениях могут быть символьными: "pi/2", "sqrt(3)", "-1/3".

1.7.2 SetStyle — оформление
  color: string          // hex. ДЕФОЛТ палитра по index
  display: "hatchRight" | "hatchLeft" | "arc" | "thickSegment"
  position: "above" | "below"   // сторона оси
  visible: boolean       // ДЕФОЛТ true
  display:
    "hatchRight"   наклонная штриховка «/» над/под осью на участке множества
                   (высота штриха 20 px, шаг 11 px, толщина 2, угол ≈63.4°).
                   ДЕФОЛТ.
    "hatchLeft"    штриховка «\» (зеркально).
    "arc"          «скобка-дуга»: на высоте 40 px от оси проводится горизонтальная
                   линия, на конечных границах — вертикальные стойки к оси;
                   на бесконечной стороне стойки нет, линия доходит до края оси
                   (толщина = appearance.graphWidth, ДЕФОЛТ 3).
    "thickSegment" жирная линия толщиной 5 px вплотную к оси (смещена на 5 px
                   в сторону position).
  position: "above" -> штриховка/дуга/линия выше оси; "below" — ниже.
  Множество рисуется только в пределах видимой области [min; max] оси:
  лучи/бесконечные части обрезаются по min/max.
  Если множество — объединение, каждая часть рисуется отдельно тем же стилем.
  Все части одного множества имеют один стиль; чтобы получить разные стили на
  одном ряду — создайте несколько множеств.

1.7.3 Автоматические граничные точки (важная связь «множество -> точки»)
  При построении множества для КАЖДОЙ КОНЕЧНОЙ границы каждой части
  автоматически создаётся точка line.points[] с:
    math.sourceSetId = set.id, math.boundaryKey = "<номер части>-left|right"
    math.coordinate = точное отображение границы (дробь/π/√ или десятичное)
    style.open  = граница выколота (leftInclusive/rightInclusive = false)
    style.color = цвет множества (если colorManual = false)
    locked = true  (нельзя удалить и править координату)
    showLabel = true, но label = "" (то есть буквы нет), showCoords = true
    -> по умолчанию на чертеже у границы стоит кружок и ПОД осью её координата.
  Исключение: если на этом ряду уже есть точка с той же координатой — новая не
  создаётся (дублей нет).
  Если граница перестала существовать (множество изменено) — её точка удаляется.
  Обратная связь: переключение style.open у locked-точки меняет включённость
  границы в самом множестве (math и запись множества пересчитываются).
  Удаление множества удаляет его граничные точки.

1.8 Точки: SceneLinePoint
  {
    id, index (ВЫХОД), axisRow: number
    math: { coordinate: `строка-выражение`, sourceSetId: string|null, boundaryKey: string|null }
    style: LinePointStyle
    built: { x, displayX, latex } | null (ВЫХОД)
    locked: boolean (ВЫХОД; true только у автоматических граничных точек)
  }
  Ручная точка: sourceSetId = null, boundaryKey = null, locked = false.
  coordinate — любое числовое выражение: "2", "-1/3", "pi/2", "sqrt(2)".
  Ошибка, если результат не конечное число.

  LinePointStyle:
    color: string                // ДЕФОЛТ "#29A2E5"
    colorManual: boolean         // true -> цвет не синхронизируется с цветом множества
    open: boolean                // false = закрашенный кружок; true = белый кружок с
                                 //   цветной обводкой (выколотая точка). ДЕФОЛТ false
    label: string                // буквенное имя точки ("A", "M₁"). ДЕФОЛТ ""
    showLabel: boolean           // показывать имя (если label непустой). ДЕФОЛТ true
    showCoords: boolean          // показывать координату. ДЕФОЛТ true
    visible: boolean             // ДЕФОЛТ true
    labelSide: "above" | "below" // сторона имени относительно оси. ДЕФОЛТ "above"
    labelColor: "point" | "axis" // цвет имени: цвет точки / цвет подписей оси. ДЕФОЛТ "point"
    coordSide: "above" | "below" // сторона координаты. ДЕФОЛТ "below"
    coordColor: "point" | "axis" // цвет координаты. ДЕФОЛТ "axis"
    perpendicular: boolean       // пунктирный вертикальный перпендикуляр. ДЕФОЛТ false

  ВИДНО:
    - Кружок радиуса appearance.pointRadius (ДЕФОЛТ 6) на оси своего ряда.
    - Имя: шрифт appearance.pointLabelFontSize (ДЕФОЛТ 32), курсив.
    - Координата: шрифт appearance.labelFontSize (ДЕФОЛТ 22). Дроби/π/корни
      отображаются через формульную вёрстку (LaTeX-подобную).
    - Если имя и координата на ОДНОЙ стороне и координата не требует формульной
      вёрстки -> одна строка "A (3)". Иначе — две отдельные подписи.
    - perpendicular=true: линия через всю высоту холста (через ВСЕ ряды),
      штрих "5 4", толщина appearance.projectionWidth (1.2), цвет
      appearance.projectionColor ("#8A93A6"), opacity 0.55.
    - Подписи точек в line не раскладываются автоматически (стороны задаются явно).

1.9 Порядок слоёв (снизу вверх)
  перпендикуляры -> множества -> ось, засечки, подписи засечек, подпись оси -> точки и подписи.

1.10 Минимальный пример (1D)
  Множество x > 2 штриховкой над осью с выколотой точкой 2:
  {
    "version":1,"space":"line",
    "line":{
      "axis":{"name":"x","unit":"","min":"-5","max":"5","majorStep":"1"},

      "axisRowCount":1,
      "sets":[{"id":"s1","index":1,"axisRow":0,
        "math":{"kind":"ray","left":"","right":"","leftOp":"<","rightOp":"<=","rayOp":">","rayBoundary":"2","freeformInput":""},
        "style":{"color":"#29A2E5","display":"hatchRight","position":"above","visible":true},

    // (+ общие поля PlotScene). После построения программа сама добавит locked-точку

  }


================================================================================
2. РЕЖИМ «ПЛОСКОСТЬ» (2D) — space = "plane"
================================================================================

2.1 Что это
  Декартова система координат с осями-стрелками, необязательной сеткой и рамкой.
  На ней строятся графики функций (5 способов задания) и точки (4 способа
  определения), с подписями, координатами и проекциями на оси.

2.2 Оси: xAxis, yAxis (AxisSpec)
  name: string       // имя переменной. Используется и как ИМЯ ПЕРЕМЕННОЙ В ФОРМУЛАХ!
                     // xAxis.name = "t" -> в выражениях функции пишется t, не x.
                     // Пусто -> "x" / "y". Подпись: "name" или "name, unit".
  unit: string       // единица измерения. ДЕФОЛТ ""
  min, max: `строка-выражение`   // пределы. ДЕФОЛТ -5 и 5. Обязательны, max > min,
                                 // иначе чертёж не строится
  gridStep: `строка-выражение`   // шаг линий сетки. ДЕФОЛТ "1". Пусто/<=0 ->
                                 // equal: 1; independent: «красивый» шаг (~8 интервалов)
  labelStep: `строка-выражение`  // шаг засечек и подписей. Пусто -> равен gridStep
  labelFormat: "number" | "fraction" | "pi"
      "number"    десятичные подписи: 0,5   (десятичная запятая)
      "fraction"  обыкновенные дроби: ½, ¾, 7/8 (знаменатель до 24; иначе десятичная)
      "pi"        кратные π: π/2, 3π/4, 2π (знаменатель до 24; иначе десятичная)
  markRule: "all" | "zeroOnly" | "zeroAndFirst" | "selected"
      "all"          засечки и подписи во всех кратных labelStep значениях
                     строго внутри (min; max) (крайние значения не отмечаются)
      "zeroOnly"     только 0 (если 0 внутри [min; max])
      "zeroAndFirst" 0 и первое положительное деление (если нуля нет — последнее)
      "selected"     только значения из selectedMarks, попадающие в [min; max]
  selectedMarks: string          // для "selected": значения через запятую/";"/перенос строки.
                                 // Выражения допустимы: "pi/2, pi, 3*pi/2"
  Засечки и подписи привязаны к кратным labelStep (отсчёт от нуля, в отличие от 1D).
  Сетка привязана к кратным gridStep, независимо от markRule.
  Для 0: засечка не рисуется; подпись "0" ставится слева-снизу от начала осей;
  если нули обоих осей отмечены — подпись нуля одна.

2.3 Положение осей и сетка
  Ось x лежит на y = 0, ось y — на x = 0. Если 0 вне диапазона — ось «прижимается» к
  ближайшему краю области. Оси идут от края до края области, стрелка на положительном
  конце (вправо/вверх), кончик стрелки на границе области. Длина стрелки
  appearance.arrowSize (24), толщина axisWidth (3).
  Название оси x — под осью у правого конца; y — слева от оси у верхнего конца
  (курсив). Если ось на краю, названия уходят на свободные поля.
  grid.visible: true -> линии сетки по всей области (цвет gridColor "#CAD1E0",
  толщина gridWidth 1). false -> сетки нет (засечки остаются).
  appearance.frame: true -> рамка вокруг области (frameColor "#CAD1E0", frameWidth 2).

2.4 Масштаб и размещение (axisScaleMode)
  Холст ВСЕГДА имеет размер appearance.width x appearance.height (ДЕФОЛТ 720x720).
  "equal"        единый масштаб по обеим осям (клетки квадратные). Масштаб =
                 min(доступная ширина/(xMax-xMin), доступная высота/(yMax-yMin)).
                 Чертёж центрируется; если область не квадратная — график УЖЕ
                 холста по меньшей стороне, а не растянут. ДЕФОЛТ.
  "independent"  независимые масштабы; область графиков вписывается в холст с
                 соотношением сторон plotAspectRatio ("1:1","4:3","3:2","16:9","3:4";
                 ДЕФОЛТ "4:3"). Клетки могут быть прямоугольными.
  Поля под подписи (gutters) резервируются автоматически: слева, если ось y у левого
  края (xMin >= 0); справа, если у правого (xMax <= 0); аналогично сверху/снизу.
  Поле appearance.equalScale в рендере НЕ используется (устаревшее); режим задаёт
  только axisScaleMode.

2.5 Оформление: appearance (PlotAppearance), значения по умолчанию
  width 720, height 720, padding 16,
  axisWidth 3, axisColor "#1A2236", arrowSize 24,
  gridWidth 1, gridColor "#CAD1E0",
  frame true, frameWidth 2, frameColor "#CAD1E0",
  tickWidth 2, tickSize 6,
  labelFontFamily "SB Serif Text, KaTeX_Main, ui-serif, serif", labelFontSize 22, labelColor "#1A2236",
  graphWidth 3 (толщина линий графиков по умолчанию), pointRadius 6,
  pointLabelFontSize 32, pointLabelFontFamily (как у labelFontFamily),
  projectionWidth 1.2, projectionColor "#8A93A6".

2.6 ГРАФИКИ: SceneGraph
  {
    id: string, index: number (ВЫХОД)
    math: GraphMath
    style: GraphStyle
    built: BuiltGraph | null (ВЫХОД: ломаные), dirty, error (ВЫХОД)
  }

2.6.1 GraphStyle
  color: string          // ДЕФОЛТ палитра по index
  width: number | null   // null -> appearance.graphWidth (3)
  label: string          // НЕ ВИДНО на чертеже: показывается только в заголовке карточки UI
  visible: boolean       // false -> график построен, но не рисуется (по нему всё равно
                         //   можно ставить точки и искать пересечения)
  Линии графика: скруглённые концы и стыки, обрезаются по области (clip).

2.6.2 GraphMath — общие поля
  kind: "explicit" | "implicit" | "piecewise" | "qualitative" | "piecewise-linear" | "parametric"
  domainFrom, domainTo: `строка-выражение` (необязательные; допускают -inf/+inf)
      Пределы построения по горизонтали. Итог = пересечение с [xMin; xMax] области.
      Если итоговый отрезок пуст -> ошибка «Пределы построения функции заданы неверно».
      Применяются к: explicit, implicit, qualitative, piecewise-linear.
      НЕ применяются к: piecewise (там границы задаёт каждый участок).
      Для parametric — это диапазон параметра t.
  Неиспользуемые для выбранного kind поля (expression/equation/pieces/anchors/...)
  игнорируются; их можно оставлять с дефолтами.
  Переменные в формулах: имена осей (xAxis.name, yAxis.name — для implicit).

2.6.3 kind = "explicit"   — явная функция y = f(x)
  Нужно: expression (`строка-выражение` от переменной xAxis.name).
  ВИДНО: кривая по 900 выборкам на [domainFrom; domainTo] ∩ область.
    - Разрывы: в точках, где значение не определено (NaN/∞) или скачок > 8 высот
      области — линия рвётся (вертикальные асимптоты не соединяются).
    - Значения по y обрезаются на 4 высотах области выше/ниже (дальше — за кадром).
  Особенности: подходит для графиков вида y = f(x), включая модуль, корни, тригонометрию,
  ln, степени. Вертикальные прямые x = c так задать нельзя (см. implicit).
  Точки: можно onGraph по x и intersection. Координату точки на таком графике можно
  двигать вручную (график однозначный).

2.6.4 kind = "implicit"   — неявная кривая F(x, y) = G(x, y)
  Нужно: equation: строка с РОВНО ОДНИМ знаком "=", обе части — выражения от
  xAxis.name и yAxis.name. Пример: "x^2 + y^2 = 4", "x = 2", "y = x^2".
  ВИДНО: линия уровня F−G = 0, найденная «марширующими квадратами» на сетке 220x220
  в прямоугольнике [domainFrom; domainTo] x [yMin; yMax]. Подходит для окружностей,
  эллипсов, гипербол, вертикальных прямых.
  Ограничения: кривая находится по смене знака F−G; кратные корни без смены знака
  (например (y-x)^2 = 0, x^2+y^2 = 0) могут не отрисоваться. Точность ~ размер клетки
  сетки. Выборка по оси y — только внутри области.
  Точки: onGraph по x даёт все точки кривой с этим x (для окружности — две);
  при вертикальном отрезке берётся середина; intersection работает. Координату такой
  точки вручную менять нельзя (график не однозначен).

2.6.5 kind = "piecewise"   — кусочно-аналитическая функция
  Нужно: pieces: PiecewisePiece[] (>= 1).
    PiecewisePiece { expression: `строка-выражение` от x,
                     from: `строка-выражение`|"" (пусто = -inf),
                     to:   `строка-выражение`|"" (пусто = +inf),
                     includeFrom: boolean (ДЕФОЛТ true),
                     includeTo: boolean (ДЕФОЛТ false) }
  Условия: to > from; формула у каждого участка обязательна.
  ВИДНО: каждый участок — отдельная кривая на [from; to] ∩ область по [xMin; xMax].
  includeFrom/includeTo НА ЧЕРТЁЖ САМИ НЕ ВЛИЯЮТ: кружки на стыках автоматически не
  рисуются. Они определяют лишь «закрашенность» точек, ставимых по графику (см. 2.7.3).
  Чтобы показать выколотую/закрашенную точку на стыке — добавьте точку (mode "onGraph"
  по x стыка): для каждой ветви появится решение с правильным open.
  domainFrom/domainTo игнорируются.

2.6.6 kind = "qualitative"   — гладкий «качественный» график по опорным точкам
  Нужно: anchors: AnchorPoint[] (>= 2), AnchorPoint { x, y: `строка-выражение`,
         kind: "plain" | "min" | "max" }.
  extendEnds: boolean (ДЕФОЛТ true).
  Смысл kind:
    "plain" — обычная опорная точка: кривая проходит через неё без излома, наклон
              подбирается так, чтобы не возникало лишних экстремумов (монотонная
              интерполяция Эрмита; если соседние наклоны разных знаков — в точке
              горизонтальная касательная).
    "min"/"max" — точка экстремума: касательная горизонтальна. (min и max
              ведут себя одинаково в расчёте; различаются только смыслом.)
  Две "plain"-точки дают прямую.
  extendEnds = true  -> кривая гладко продолжается за крайние точки до краёв области
                        (сохраняется наклон и кривизна).
  extendEnds = false -> кривая обрывается на крайних опорных точках.
  X-координаты опорных точек должны быть различны (не проверяется строго, но при
  равных x кривая вырождается).
  Точки: mode "anchor" (выбрать опорную точку) и onGraph (по x или по anchorIndex).
  Сами опорные точки на чертеже автоматически не рисуются — их нужно отметить точками.

2.6.7 kind = "piecewise-linear"   — ломаная по опорным точкам
  Нужно: anchors (>= 2) с различными x; kind опорной точки игнорируется.
  extendEnds: boolean (ДЕФОЛТ true).
  ВИДНО: ломаная точно через вершины (углы совпадают с заданными точками), опорные
  точки сортируются по x.
  extendEnds = true  -> крайние отрезки продолжаются прямолинейно до краёв области.
  extendEnds = false -> ломаная заканчивается в крайних опорных точках.
  Ошибка при равных x опорных точек. Используйте для отрезков и ломаных (вместо
  piecewise с участками), если нужно точное попадание углов.
  Точки: anchor и onGraph, как у qualitative.

2.6.8 kind = "parametric"   — параметрическая кривая (в UI НЕТ; возможна только через JSON)
  Нужно: xExpression, yExpression (`строка-выражение` от переменной "t").
  domainFrom/domainTo — диапазон t (ДЕФОЛТ 0 ... 2π). 900 выборок; без разрывов и без
  обрезки по y (только clip по области). Рекомендуется не использовать в ручном режиме.

2.7 ТОЧКИ: ScenePoint
  {
    id, index (ВЫХОД)
    math: PointMath
    style: PointStyle
    built: PointSolution[] | null (ВЫХОД), dirty, error (ВЫХОД)
  }
  Одна запись ScenePoint может давать НЕСКОЛЬКО решений (built.length > 1),
  например пересечение двух кривых в нескольких местах. Каждое решение рисуется
  как отдельная точка и может быть отдельно скрыто (show) или оформлено (style).

2.7.1 PointMath
  mode: "plane" | "onGraph" | "intersection" | "anchor"
  x, y: `строка-выражение`      // для plane; для onGraph — только x
  graphId: string | null        // график (onGraph, anchor; первый график для intersection)
  graphIdB: string | null       // второй график (intersection)
  anchorIndex: number | null    // 0-based индекс опорной точки (anchor; onGraph по якорю)
  ДЕФОЛТ: mode "plane", x "", y "", остальное null.

2.7.2 Режимы определения точки
  mode = "plane"   — свободная точка по координатам
    Нужно: x, y (обе непустые числовые выражения: "2", "-1/3", "pi/2", "sqrt(2)").
    Решение: ровно одно. ВИДНО: точка в (x, y) даже если она вне области осей
    (не обрезается, не проверяется).
    Координаты в подписи: если в выражении есть "pi", "π", "sqrt" или "/" — точное
    представление (дробь, кратное π, √n; иначе десятичное до 4 знаков), иначе —
    десятичное число. Координаты можно менять вручную (карточка точки).
    Применять только для точек, чьё положение ЗАДАНО числами в условии. Для точек,
    которые лежат на графике или являются пересечением — используйте onGraph /
    intersection (иначе они «отвязаны» от графиков).

  mode = "onGraph"  — точка на графике с заданным x
    Нужно: graphId (график уже построен), x (`строка-выражение`).
    Решения: все точки построенной кривой с этим x:
      explicit/qualitative/piecewise-linear — одна (y считается по ломаной графика);
      implicit — столько, сколько ветвей пересекает вертикаль;
      piecewise — по одному решению на каждую ветвь, определённую в этом x.
    Если x вне области определения построенной кривой -> ошибка «В этой координате
    график не определён».
    y — по ломаной графика (практически точно; y обрезан на 4 высотах области).
    Для qualitative/piecewise-linear при anchorIndex != null решением будет опорная
    точка (x не используется).
    Подпись y: точное представление по значению (дробь/π/√n/десятичное).
    Для однозначных графиков (не implicit/parametric) x можно двигать вручную —
    точка остаётся на графике.

  mode = "intersection" — пересечение двух графиков
    Нужно: graphId, graphIdB — два РАЗНЫХ построенных графика.
    Решения: все пересечения построенных ломаных, лежащие внутри области осей
    (с допуском 1e-9), отсортированы по x, затем по y; близкие (<1e-3) склеиваются.
    Если пересечений нет -> ошибка «Пересечений в текущей области не найдено».
    Координаты НЕ вводятся и вручную НЕ редактируются — они вычислены.
    Касание без пересечения ломаных (двойной корень) может не обнаружиться.
    Если на чертеже нужно ВСЕ пересечения — одна запись; нужно ОДНО из них — оставить
    остальные решения с show=false (или свернуть их в UI).

  mode = "anchor" — опорная точка качественного графика / ломаной
    Нужно: graphId (kind "qualitative" или "piecewise-linear"), anchorIndex.
    Решение: ровно одно — координаты опорной точки (подпись использует её исходные
    строки x, y, т. е. "pi/2" отображается как π/2).
    Координаты не редактируются (заданы в графике).

2.7.3 PointStyle (общий для всех режимов)
  color: string         // ДЕФОЛТ "#29A2E5". Для режимов onGraph/intersection/anchor UI
                        //   подставляет цвет соответствующего графика
  open: boolean         // false: закрашенная; true: выколотая (белая заливка, цветная
                        //   обводка толщиной 2). ДЕФОЛТ false
  label: string         // буквенное имя ("A"). ДЕФОЛТ ""
  showCoords: boolean   // показывать "(x; y)" рядом. ДЕФОЛТ false
  visible: boolean      // false -> точка НЕ рисуется целиком (маркер, подпись и проекции).
                        //   Нужно, чтобы использовать точку «служебно». ДЕФОЛТ true
  projectX: boolean     // пунктир от точки к оси x + засечка на оси. ДЕФОЛТ false
  projectY: boolean     // пунктир от точки к оси y + засечка. ДЕФОЛТ false
  labelProjectionX: boolean   // подпись значения x у проекции под осью x.
                              //   РАБОТАЕТ ТОЛЬКО при projectX = true. ДЕФОЛТ false
  labelProjectionY: boolean   // подпись значения y у проекции слева от оси y.
                              //   РАБОТАЕТ ТОЛЬКО при projectY = true. ДЕФОЛТ false
  labelPlacement?: "auto" | "top" | "topRight" | "right" | "bottomRight" |
                   "bottom" | "bottomLeft" | "left" | "topLeft"
                        // положение подписи; НЕТ в UI, только JSON. ДЕФОЛТ "auto"
  Подпись точки = [label] + [ "(dx; dy)" если showCoords ], через пробел, одним блоком.
  Пустая подпись (label == "" и showCoords == false) не рисуется.
  "auto": подпись ставится в одно из 8 направлений с минимальным штрафом
  (пересечения с графиками, осями, другими подписями, выход за поле). Фиксированное
  направление в раскладке не участвует.
  Проекции: линия "5 4" толщиной projectionWidth цветом projectionColor до положения
  оси (если ось сдвинута к краю — до неё).
  Размер маркера: pointRadius (6). Подпись: pointLabelFontSize (32), курсив.
  Правило видимости решения: point.style.visible И solution.show И merged.visible.
  merged = { ...point.style, ...solution.style }.

2.7.4 PointSolution (ВЫХОД, но влияет на вид)
  { x, y: number, displayX, displayY: string, show: boolean, style?: Partial<PointStyle> }
  show — индивидуальное скрытие одного из решений. style — индивидуальный override:
  для точек на piecewise автоматически выставляется open (по включённости границы
  ветви); при выборе решения вручную можно менять любые поля PointStyle.

2.8 Порядок слоёв (снизу вверх)
  белый фон -> сетка -> рамка -> оси со стрелками -> засечки и подписи -> названия осей ->
  графики (обрезаны по области) -> проекции и маркеры точек -> подписи точек.

2.9 Минимальный пример (2D): точка пересечения двух прямых
  graphs: [
   {id:"g1",index:1,math:{kind:"explicit",expression:"x+1",equation:"",pieces:[],anchors:[],domainFrom:"",domainTo:""},
    style:{color:"#29A2E5",width:null,label:"",visible:true},built:null,dirty:true,error:null},
   {id:"g2",index:2,math:{kind:"explicit",expression:"-x+3",equation:"",pieces:[],anchors:[],domainFrom:"",domainTo:""},
    style:{color:"#FF9935",width:null,label:"",visible:true},built:null,dirty:true,error:null}]
  points: [
   {id:"p1",index:1,math:{mode:"intersection",x:"",y:"",graphId:"g1",graphIdB:"g2",anchorIndex:null},
    style:{color:"#29A2E5",open:false,label:"A",showCoords:true,visible:true,projectX:false,projectY:false,labelProjectionX:false,labelProjectionY:false},
    built:null,dirty:true,error:null}]
  // Две разные точки (свободная plane и intersection) с одними координатами выглядят
  // на чертеже одинаково; различие только в способе определения (mode) и в том, что
  // intersection пересчитывается при изменении графиков.


================================================================================
3. РЕЖИМ «ПРОСТРАНСТВО» (3D) — space = "space"
================================================================================

3.1 Что это
  Школьное изображение многогранника (одного тела на сцене) в аксонометрии: рёбра
  тела (видимые — сплошные, скрытые — пунктир), точки (на ребре/прямой, на грани,
  на пересечении прямой и плоскости, на пересечении плоскости и ребра, граничные
  точки линии пересечения), прямые/отрезки/векторы, секущие плоскости (сечение
  заливкой), автоматические линии пересечения плоскостей. Поворот вокруг вертикальной
  оси (yaw).
  Геометрия задаётся ТОЛЬКО семантически; координаты вершин в JSON не хранятся.
  Холст: appearance.width x appearance.height в данных space3d (ДЕФОЛТ 720x720),
  проекция вписывается в холст с отступом appearance.padding (24).
  Поля xAxis/yAxis/graphs/points верхнего уровня PlotScene в этом режиме не используются.

3.2 Структура: SpaceSceneData (space3d)
  {
    shapeKind: "parallelepiped" | "pyramid" | "prism" | null
               // "cone","sphere","cylinder" есть в типе, но в UI ОТКЛЮЧЕНЫ и не строятся
    baseVerticesInput: string      // буквы вершин основания (см. 3.3)
    figureConstraints: объект ограничений (зависит от shapeKind, 3.4)
    figureBuilt: boolean           // в экспорте: фигура была построена. Если false — на
                                   // чертеже ничего нет
    points: SpacePointJson[]       // {id,index,label,definition,style,built}
    lines:  SpaceLineJson[]        // {id,index,label,definition,style,built}
    planes: SpacePlaneJson[]       // {id,index,label,definition,style,built}
    view: SpaceViewParamsJson      // 3.9
    appearance: SpaceAppearance    // 3.10
  }
  Фигура (вершины/рёбра/грани) в JSON не хранится — она восстанавливается из
  shapeKind + baseVerticesInput + figureConstraints (только при figureBuilt = true).
  Все объекты (точки/прямые/плоскости) требуют построенную фигуру.
  Порядок точек важен: точка может ссылаться только на ранее определённые точки/
  прямые/плоскости (разрешение идёт по списку).

3.3 Тело и обозначения вершин
  3.3.1 Ввод baseVerticesInput
    Из строки берутся только БУКВЫ (латиница и кириллица, регистр не важен;
    цифры, пробелы, запятые, подчёркивания игнорируются). Примеры: "A, B, C, D", "ABCD".
    Нормализация: КИРИЛЛИЦА преобразуется в латиницу по РАСКЛАДКЕ КЛАВИАТУРЫ (а не по
    звучанию): А->F, В->D, С->C, Е->T, К->R, М->V, Н->Y, О->J, Р->H, Т->N, Х->[ (не
    буква, будет заменена на первую свободную). Дубликаты и нераспознанные буквы
    заменяются на первую свободную латинскую A..Z, затем на букву с индексом.
    Лучше сразу вводить латиницу.
    Надстрочные/подстрочные обозначения верхних вершин: "A₁" (буква + нижний индекс 1).
  3.3.2 Правила по типам
    parallelepiped: первые 4 буквы -> нижнее основание A,B,C,D по порядку обхода
      (A-B-C-D по кругу). Верхние вершины: A₁,B₁,C₁,D₁ (над A,B,C,D).
      Меньше 4 букв — ошибка.
    pyramid: первая буква — вершина (apex), остальные (минимум 3) — вершины основания
      по порядку обхода (правильный n-угольник). Всего >= 4 букв.
    prism: минимум 3 буквы — нижнее основание по порядку; верхнее получает те же буквы
      с индексом ₁ (A₁, B₁, ...). Число сторон основания = число букв.
  3.3.3 Идентификаторы элементов тела (стабильные; именно они используются в JSON)
    parallelepiped:
      вершины:  pp-v-A, pp-v-B, pp-v-C, pp-v-D, pp-v-A1, pp-v-B1, pp-v-C1, pp-v-D1
                (идентификаторы по ПОЗИЦИИ, не по введённым буквам)
      рёбра:    e-ab, e-bc, e-cd, e-da, e-a1b1, e-b1c1, e-c1d1, e-d1a1,
                e-aa1, e-bb1, e-cc1, e-dd1
      грани:    f-bottom (ABCD), f-top (A₁B₁C₁D₁), f-front (ABB₁A₁),
                f-back (DCC₁D₁), f-left (ADD₁A₁), f-right (BCC₁B₁)
    pyramid (n = число вершин основания, i = 0..n-1):
      вершины:  pyr-v-apex, pyr-v-b0 ... pyr-v-b{n-1} (b0 — первая буква основания,
                т. е. вторая буква ввода)
      рёбра:    pyr-e-b{i} (основание: b{i} -> b{i+1 mod n}),
                pyr-e-s{i} (боковое: apex -> b{i})
      грани:    pyr-f-base, pyr-f-side-{i} (apex, b{i+1 mod n}, b{i})
    prism:
      вершины:  prism-v-b0..b{n-1} (нижние), prism-v-t0..t{n-1} (верхние)
      рёбра:    prism-e-b{i} (нижнее), prism-e-t{i} (верхнее), prism-e-l{i} (боковое b{i}->t{i})
      грани:    prism-f-base, prism-f-top, prism-f-side-{i} (b{i}, b{i+1}, t{i+1}, t{i})
  3.3.4 Геометрия тела (3D, фиксирована)
    parallelepiped: единичные рёбра в локальном базисе (AB, AD, AA₁); проекция на чертеже
      регулируется ограничениями (3.4).
    pyramid: основание — правильный n-угольник радиуса 1 в плоскости z=0, первая вершина
      основания в (1,0,0), обход против часовой; высота 2. Вершина пирамиды: над центром
      основания (apexOnCenter=true) либо над первой вершиной основания (false).
    prism: прямая призма: основание — правильный n-угольник радиуса 1, высота 2.
    Размеры в JSON/UI не задаются (чертёж схематичный).

3.4 Ограничения тела: figureConstraints
  parallelepiped: { rectangular: boolean, equilateral: boolean, badAngleDeg: number }
    rectangular (ДЕФОЛТ true): true — боковое ребро AA₁ рисуется ВЕРТИКАЛЬНО (прямоугольный);
        false — наклонно (75° к AD) — «наклонный параллелепипед» на чертеже.
    equilateral (ДЕФОЛТ false): true — все рёбра одной длины (куб); false — рёбра разной
        длины (AD:AB:AA₁ ≈ 1 : 1.15 : 0.95 в единицах базового ребра).
    badAngleDeg (ДЕФОЛТ 35, диапазон 10–60): визуальный угол ∠BAD на чертеже (наклон «глубинных»
        рёбер); 3D-геометрию не меняет.
  pyramid: { apexOnCenter: boolean, equilateral: boolean, badAngleDeg: number }
    apexOnCenter (ДЕФОЛТ true): вершина над центром основания (правильная пирамида);
        false: над первой вершиной основания (боковое ребро к ней перпендикулярно основанию).
    equilateral: сохраняется, но в геометрии/проекции пирамиды НЕ используется.
    badAngleDeg: как выше (10–60, ДЕФОЛТ 35) — ракурс основания.
  prism: { straight: boolean, equilateral: boolean, badAngleDeg: number }
    straight (ДЕФОЛТ false): влияет только на ракурс бокового направления на чертеже
        (аналог apexOnCenter пирамиды: false — «как над центром», true — «как над первой
        вершиной основания»). Тело всегда геометрически прямая призма.
    equilateral: сохраняется, НЕ используется.
    badAngleDeg: как выше.
  Смена shapeKind сбрасывает фигуру и ставит ограничения по умолчанию для нового вида.
  Изменение constraints после построения пересчитывает фигуру и вершины.

3.5 ТОЧКИ: SpacePoint
  {
    id, index (ВЫХОД), label: string, definition: SpacePointDefinition,
    style: { color: string, visible: boolean, labelPlacement?: LabelPlacement },
    built: boolean
  }
  Имя точки: латинская буква (первая буква нормализуется по раскладке так же, как у
  вершин) + необязательный суффикс (например "M1", "K₂"). Пусто -> первая свободная
  буква A..Z, не занятая вершинами и другими точками. При конфликте — первая свободная.
  ДЕФОЛТ цвета: палитра по index. Если точка лежит в построенной плоскости (допуск 1e-3) —
  её цвет автоматически становится цветом этой плоскости (при нескольких — последней по списку).
  ВИДНО: кружок радиуса appearance.pointRadius (6) цветом точки + подпись label
  (курсив, appearance.labelFontSize 32). Цвет подписи: цвет рёбер тела (если
  view.pointLabelsUseEdgeColor != false, ДЕФОЛТ true) иначе цвет точки.
  Положение подписи — автораскладка (labelPlacement "auto"/8 направлений — только JSON).
  Вершины тела маркерами НЕ рисуются — только их подписи (курсив, цвет labelColor).
  Точка без label подписи не имеет.

  definition.kind — способ определения:

  kind = "onLine"  — точка на прямой AB (на ребре, диагонали, или любой прямой через
                     две точки), в заданной области
    pointAId, pointBId: id двух различных точек (вершины тела или другие точки).
    region: "before" | "between" | "after"
      "between"  P на отрезке AB (между A и B)
      "before"   P на продолжении за A (слева от A)
      "after"    P на продолжении за B
    Положение: параметр t, P = A + t·(B − A).
      ratioMode "auto":     t = lineParam, с ограничением по области:
                            between: 0.02 ≤ t ≤ 0.98; before: t ≤ −0.02; after: t ≥ 1.02.
                            ДЕФОЛТЫ lineParam: before −0.3, between 0.4 (UI: ползунок),
                            after 1.35.
      ratioMode "explicit": t из отношения ratioA : ratioB (оба > 0):
                            between: AP : PB = ratioA : ratioB  (t = A/(A+B));
                            before:  AP = (ratioA/ratioB)·AB, P за A (t = −A/B);
                            after:   BP = (ratioA/ratioB)·AB, P за B (t = 1 + A/B).
    При создании через UI, если носителя AB ещё нет (ни ребра, ни прямой, ни
    коллинеарной прямой), автоматически создаётся вспомогательная прямая twoPoints A,B
    (visualKind "segment" для between, иначе "line") — она появится на чертеже.
    Для пирамиды и призмы все пользовательские точки, лежащие вблизи ребра тела, программа
    «притягивает» к этому ребру (чтобы точка в проекции точно легла на линию ребра).

  kind = "onFace"  — точка на грани тела
    faceId: id грани (3.3.3)
    placement: "arbitrary" | "center"
      "center":    среднее арифметическое вершин грани (центр)
      "arbitrary": точка с аффинными координатами faceU, faceV ∈ [0;1] внутри грани
                   (UI создаёт faceU = faceV = 0.35).
        Четырёхугольная грань (v0,v1,v2,v3): низ = lerp(v0,v1,u), верх = lerp(v3,v2,u),
          P = lerp(низ, верх, v). Треугольная: P = (1−u−v)·v0 + u·v1 + v·v2.
          Для грани из >4 вершин: веер треугольников, u выбирает треугольник.
    faceU, faceV: number.

  kind = "linePlaneIntersection"  — пересечение прямой и плоскости
    lineId: id ребра тела ИЛИ построенной прямой (SpaceLine.id)
    planeId: id грани тела ИЛИ построенной плоскости (SpacePlane.id)
    Ошибки: прямая/плоскость не построены; прямая параллельна плоскости или лежит в ней.
    Точка может лежать ВНЕ тела (на продолжении прямой).

  kind = "planeEdgeIntersection"  — пересечение плоскости с ребром тела
    planeId, edgeId. Ошибка, если плоскость не пересекает ребро в одной точке.
    Создаётся UI-ходом «Из построения» (см. 3.8).

  kind = "planeIntersectionBoundary" — граничная точка линии пересечения двух плоскостей
                                       внутри тела
    planeAId, planeBId: две плоскости; endpoint: 0 | 1 (какой конец отрезка пересечения
    внутри тела: 0 — начало (t0), 1 — конец (t1)).
    Создаётся автоматически при построении прямой planeIntersection и ходом «Из построения».

  kind = "onSpaceLine" (ЕСТЬ в данных и вычисляется, но в UI нет способа создать):
    lineId, lineParam — P = origin + t·dir на носителе построенной прямой.
  kind = "builtin" — служебный (вершина тела); в points[] пользователя не используется.

3.6 ПРЯМЫЕ / ОТРЕЗКИ / ВЕКТОРЫ: SpaceLine
  {
    id, index (ВЫХОД), label: string, definition: SpaceLineDefinition,
    style: { color: string, width: number, visible: boolean, visualKind: "segment"|"line"|"vector" },
    built: boolean
  }
  style.width — толщина (ДЕФОЛТ 3 = appearance.lineWidth). Скрытые части (за телом) рисуются
  пунктиром appearance.hiddenDash ("20 14"), видимые — сплошной линией.
  label авто: для twoPoints — склейка имён точек ("AB"), иначе a, b, c...; НА ЧЕРТЁЖЕ ПОДПИСЬ
  ПРЯМОЙ НЕ РИСУЕТСЯ (только в списке UI).

  definition.kind:
  kind = "twoPoints"  — через две точки
    aId, bId: id двух РАЗЛИЧНЫХ точек (вершины/другие точки).
    visualKind:
      "segment" — отрезок A→B (ДЕФОЛТ)
      "line"    — прямая: отрезок AB, продлённый в обе стороны на appearance.lineExtension
                  (ДЕФОЛТ 0.35) длины AB; для параллелепипеда продление дополнительно
                  охватывает проекции всех остальных точек сцены на эту прямую (то есть
                  прямая может оказаться длиннее, чтобы «дотянуться» до них)
      "vector"  — отрезок с наконечником-стрелкой в точке B (размер appearance.arrowSize 24)
  kind = "planeIntersection" — линия пересечения двух плоскостей
    planeAId, planeBId: id граней или построенных плоскостей (РАЗЛИЧНЫЕ, не параллельные),
    endpointAId?, endpointBId?: id двух граничных точек (planeIntersectionBoundary), которые
      создаются автоматически вместе с линией.
    visualKind:
      "segment" — отрезок линии внутри тела (между граничными точками) (ДЕФОЛТ)
      "line"    — то же, продлённое с обеих сторон на lineExtension × длина отрезка
      ("vector" для этого вида не предназначен)
    Если пересечение не проходит через тело — линия не строится (ошибка).
  Ошибка "Прямая не определена": носитель не найден (точка/плоскость удалены или невалидны).

3.7 ПЛОСКОСТИ: SpacePlane
  {
    id, index (ВЫХОД), label: string, definition: SpacePlaneDefinition,
    style: { color: string, visible: boolean, helperOpacity: number },
    built: boolean
  }
  label авто: для threePoints — "(ABC)" по именам точек; иначе греческая буква α, β, γ ...
  (на чертеже не рисуется).
  helperOpacity (ДЕФОЛТ 0.45) хранится, но рендером НЕ используется.
  ВИДНО (для построенной видимой плоскости):
    - сечение тела этой плоскостью (многоугольник, не менее 3 вершин) заливается цветом
      плоскости с прозрачностью appearance.planeFillOpacity (ДЕФОЛТ 0.5);
    - контур сечения цветом плоскости толщиной appearance.lineWidth (3); скрытые части
      контура — пунктиром;
    - вспомогательные линии (толщина вдвое тоньше): продолжения от точек, задающих плоскость и
      лежащих вне тела, к сечению (чтобы показать, откуда плоскость «берётся»).
    - заливки плоскостей рисуются «от дальних к ближним» (алгоритм художника): порядок
      определяется view.planeFillDepthMode.
    Если плоскость не пересекает тело (сечение пустое) — заливки нет.

  definition.kind:
  kind = "threePoints"      — по трём точкам
    aId, bId, cId: три РАЗЛИЧНЫЕ неколлинеарные точки. Ошибка: «Точки коллинеарны».
  kind = "pointAndLine"     — через точку и прямую
    pointId: id точки; lineId: id ребра тела ИЛИ построенной прямой.
    Ошибка, если точка лежит на прямой.
  kind = "twoLines"         — через две прямые
    lineAId, lineBId: РАЗЛИЧНЫЕ прямые (ребро или построенная прямая), которые пересекаются
    или параллельны. Ошибки: прямые совпадают; скрещивающиеся.
  kind = "lineParallelToLine" — через прямую параллельно другой прямой
    throughLineId: прямая, которая лежит в плоскости;
    parallelToLineId: прямая, которой плоскость параллельна (НЕ параллельна throughLineId).
    Ошибка, если прямые параллельны.
  Для всех: две плоскости с одинаковым положением допустимы, но для линии пересечения
  нужны разные непараллельные плоскости.

3.8 Составные ходы UI («Из построения»)
  Эти ходы лишь создают обычные объекты из списка выше:
  - Точки «из построения»: для каждой построенной плоскости и каждого ребра тела, которое
    она пересекает в одной точке — создаётся точка planeEdgeIntersection;
    для каждой пары построенных плоскостей, пересекающихся внутри тела — две точки
    planeIntersectionBoundary (endpoint 0 и 1). Уже существующие не дублируются.
  - Прямая «из построения»: линия planeIntersection для пары плоскостей; вместе с ней
    создаются обе граничные точки пересечения (цвет = цвет линии) и в линию записываются
    endpointAId/endpointBId.
  - Автоматические линии пересечения всех пар плоскостей: view.showPlaneIntersections.

3.9 Вид: view (SpaceViewParamsJson) и ДЕФОЛТЫ
  scale: 1                   базовый масштаб (дальше уточняется автоподгонкой под холст)
  yaw: 0                     поворот вокруг вертикальной оси, градусы; 0 — исходный ракурс.
                             Значения в пределах ±4° от нуля «прилипают» к 0 (в UI).
  pitch: 0                   зарезервировано (в UI не меняется)
  depthLength: 0.875         визуальная длина глубинного ребра на чертеже
  heightLength: 1.35         визуальная длина вертикального ребра на чертеже
  scaleX, scaleY: (нет)      необязательные раздельные масштабы
  visibilityMode: "school" | "legacy"
      "school"  (ДЕФОЛТ) — школьная схема видимости: фиксированный ракурс, невидимые рёбра
                          и части линий — пунктиром по правилам школьного чертежа
      "legacy"  — видимость по экранному перекрытию (окклюзия)
  planeFillByDepth: true     устаревшее; заливка всегда по глубине
  planeFillDepthMode: "plane" | "eye"
      "plane" (ДЕФОЛТ) — глубина = расстояние до плоскости изображения (вращается с yaw)
      "eye"            — пирамида: вдоль луча к «глазу»; параллелепипед: школьная ось
  showPlaneIntersections: false   true -> пунктирные линии пересечения всех пар построенных
                                  плоскостей (авто)
  showRotationEllipse: false      отладка: пунктирный эллипс вращения основания (серый)
  showViewConvergenceRays: false  отладка: красные пунктирные «лучи зрения»
  pointLabelsUseEdgeColor: true   подписи доп. точек цветом рёбер (true) / цветом точки (false)
  renderGrayscale: false          true -> все цвета (линии, плоскости, точки) в градациях серого
  Вид влияет только на проекцию, не на геометрию (точки/плоскости не перестраиваются).

3.10 Оформление: appearance (SpaceAppearance) и ДЕФОЛТЫ
  width 720, height 720, padding 24,
  edgeWidth 3 (толщина рёбер тела), edgeColor "#1A2236",
  hiddenDash "20 14" (пунктир скрытых рёбер, линий и границ сечений),
  labelFontSize 32, labelFontFamily "SB Serif Text, KaTeX_Main, ui-serif, serif", labelColor "#1A2236",
  pointRadius 6, lineWidth 3, lineExtension 0.35, arrowSize 24, planeFillOpacity 0.5.

3.11 Порядок слоёв (снизу вверх)
  белый фон -> (отладочный эллипс) -> рёбра тела -> заливки/контуры плоскостей (от дальних к
  ближним) -> автоматические пересечения плоскостей -> рёбра тела перед плоскостями ->
  прямые/отрезки/векторы -> маркеры точек -> (отладочные лучи) -> подписи вершин и точек.
  Ребро тела, полностью перекрытое нарисованным поверх (например, совпавшим с ним отрезком),
  не дублируется.

3.12 Минимальный пример (3D): куб ABCD A₁B₁C₁D₁, точка M на ребре AA₁ и сечение через B, D, M
  space3d: {
    shapeKind:"parallelepiped", baseVerticesInput:"A, B, C, D",
    figureConstraints:{rectangular:true,equilateral:true,badAngleDeg:35}, figureBuilt:true,
    points:[{id:"sp1",index:1,label:"M",
       definition:{kind:"onLine",pointAId:"pp-v-A",pointBId:"pp-v-A1",region:"between",ratioMode:"explicit",ratioA:1,ratioB:2,lineParam:0.4},
       style:{color:"#29A2E5",visible:true},built:true}],
    lines:[],
    planes:[{id:"spl1",index:1,label:"(BDM)",
       definition:{kind:"threePoints",aId:"pp-v-B",bId:"pp-v-D",cId:"sp1"},
       style:{color:"#29A2E5",visible:true,helperOpacity:0.45},built:true}],
    view:{...по умолчанию (3.9)}, appearance:{...по умолчанию (3.10)}
  }
  // Здесь точка M делит AA₁ в отношении AM : MA₁ = 1 : 2.


================================================================================
4. КРАТКАЯ СВОДКА «ВОЗМОЖНОСТЬ -> ПОЛЯ»
================================================================================

4.1 1D
  Множество: интервал       -> sets[].math{kind:"interval",left,right,leftOp,rightOp}
  Множество: луч            -> sets[].math{kind:"ray",rayOp,rayBoundary}
  Множество: объединение    -> sets[].math{kind:"freeform",freeformInput:"(a;b]; [c;+inf)"}
  Вид множества             -> sets[].style.display (hatchRight|hatchLeft|arc|thickSegment), position
  Несколько осей            -> line.axisRowCount, axisRow у объектов
  Точка (закр./выкол.)      -> points[].math.coordinate, style.open
  Подпись имени / координаты-> style.label/showLabel/labelSide/labelColor, showCoords/coordSide/coordColor
  Пунктирный перпендикуляр  -> points[].style.perpendicular
  Засечки/подписи оси       -> line.ticks.*, line.axis.*
  Мелкие деления            -> line.ticks.minorEnabled/minorDivisions/minorLabelMode

4.2 2D
  Явная функция             -> graphs[].math{kind:"explicit",expression}
  Неявная кривая            -> {kind:"implicit",equation}
  Кусочная функция          -> {kind:"piecewise",pieces[]}
  Гладкая по точкам         -> {kind:"qualitative",anchors[],extendEnds}
  Ломаная / отрезки         -> {kind:"piecewise-linear",anchors[],extendEnds}
  Ограничение по x          -> domainFrom/domainTo
  Свободная точка           -> points[].math{mode:"plane",x,y}
  Точка на графике          -> {mode:"onGraph",graphId,x}
  Пересечение графиков      -> {mode:"intersection",graphId,graphIdB}
  Опорная точка графика     -> {mode:"anchor",graphId,anchorIndex}
  Выколотая точка           -> style.open
  Подпись/координаты        -> style.label, showCoords, labelPlacement
  Проекции на оси           -> projectX/projectY (+ labelProjectionX/Y)
  Скрыть одно из решений    -> built[i].show = false
  Масштаб                   -> axisScaleMode, plotAspectRatio, appearance.width/height
  Шкалы                     -> xAxis/yAxis: gridStep, labelStep, labelFormat, markRule, selectedMarks
  Сетка/рамка               -> grid.visible, appearance.frame

4.3 3D
  Тело                      -> shapeKind, baseVerticesInput, figureConstraints
  Точка на ребре/прямой     -> points[].definition{kind:"onLine",...}
  Точка на грани            -> {kind:"onFace",...}
  Прямая/плоскость × точка  -> {kind:"linePlaneIntersection",...}
  Плоскость × ребро         -> {kind:"planeEdgeIntersection",...}
  Концы линии пересечения   -> {kind:"planeIntersectionBoundary",...}
  Отрезок / прямая / вектор -> lines[].definition{kind:"twoPoints"} + style.visualKind
  Линия пересечения плоскостей -> lines[].definition{kind:"planeIntersection"}
  Секущая плоскость         -> planes[].definition{threePoints|pointAndLine|twoLines|lineParallelToLine}
  Ракурс                    -> view.yaw, view.visibilityMode, view.planeFillDepthMode
  Чёрно-белое               -> view.renderGrayscale
  Автолинии пересечения     -> view.showPlaneIntersections


================================================================================
5. ОБЩИЕ ПРАВИЛА ДЛЯ ВСЕХ РЕЖИМОВ
================================================================================

5.1 Математические выражения (`строка-выражение`)
  Разбор безопасный (не JavaScript). Допустимо:
    числа "2", "-3.5" (десятичная запятая после цифры тоже понимается как точка),
    операторы + - * / ^ и скобки; неявное умножение: 3x, 2(x+1), 2sin(x);
    константы: pi (также Pi, PI, π), e, tau (=2π);
    функции: sqrt, cbrt, abs, sin, cos, tan, cot, asin, acos, atan, sinh, cosh, tanh,
             ln и log (оба — натуральный логарифм), log10, log2, exp, min, max, sign,
             floor, ceil, round, pow, hypot;
    символы: √ (как sqrt), π, ·, ×, ÷, − (минус), ∞;
    простой LaTeX вставляется и приблизительно конвертируется (\frac{a}{b}, \sqrt{x}, \pi, \cdot).
  Переменные: ровно имена осей (plane: xAxis.name и yAxis.name; в explicit/qualitative
  — только горизонтальная). Любая другая переменная -> ошибка «Неизвестная переменная».
  Выражение вне формулы (границы, координаты, шаги) — только число, без переменных.
  Бесконечные границы: "-inf", "inf", "+inf", "∞", "-∞" — только там, где указано.

5.2 Подписи чисел (сводка)
  Подписи засечек (plane): displayNumber по labelFormat (number|fraction|pi).
  Подписи засечек (line): всегда "number".
  Подписи координат точек (exactDisplay): целое/дробь (знаменатель до 12) -> кратное π
  (знаменатель до 12) -> ±√n (если квадрат — целое > 1) -> десятичное, округление до 4 знаков.
  Десятичный разделитель в подписях — запятая.

5.3 Построение и ошибки
  Объект с error не рисуется (в plane остаётся предыдущее успешное built, если было).
  Основные причины ошибок: пустые обязательные поля, неизвестная переменная, пределы
  осей не заданы/max<=min, ссылка на непостроенный/несуществующий объект, график не
  определён в заданном x, пересечений нет, вырожденные геометрические условия (3D).
  Одна ошибка не отменяет построение остальных объектов.

5.4 Размер и экспорт
  Результат — SVG размера холста (plane/space: appearance.width x height; line: 720 x высота).
  Подписи, шрифты, толщины заданы в пикселях холста, а не в «единицах чертежа».


================================================================================
6. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ И «МЁРТВЫЕ» ПОЛЯ (важно для анализа)
================================================================================
  - plane: GraphStyle.label НЕ рисуется на чертеже (только в UI-карточке). Подпись кривой
    на чертеже можно сделать лишь отдельной точкой с подписью.
  - plane: PointStyle.labelPlacement и space: SpacePointStyle.labelPlacement есть в JSON,
    но не имеют элемента управления в UI.
  - plane: tangents[] — зарезервировано, не рисуется.
  - plane: GraphMath.kind "parametric" — нет в UI; рендер работает.
  - plane: GraphMath.piecewise — includeFrom/includeTo не рисуют кружков сами по себе;
    domainFrom/domainTo игнорируются.
  - plane: appearance.equalScale — устаревшее, не используется (режим — axisScaleMode).
  - plane: точки (mode "plane") не проверяются на попадание в область осей и не
    обрезаются.
  - plane: пересечение ищется по ломаным; касание без пересечения может быть не найдено.
  - line: ширина холста фиксирована (720); appearance.width/height игнорируются.
  - line: у locked-точек (границы множеств) нельзя менять координату и удалять их.
  - line: у множества-объединения единый стиль для всех частей.
  - space: shapeKind cone/sphere/cylinder отключены (нет в UI).
  - space: SpacePlaneStyle.helperOpacity хранится, не используется рендером.
  - space: pitch, depthSkewX/Y, planeFillByDepth — устаревшие/зарезервированные.
  - space: подписи прямых и плоскостей на чертёж не выводятся (только вершины и точки).
  - space: figureConstraints.equilateral у пирамиды/призмы не используется.
  - space: kind "onSpaceLine" точки вычисляется, но через UI не создаётся.
  - space: размеры тела не задаются (схематичный чертёж).
